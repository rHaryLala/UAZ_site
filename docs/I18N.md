# Site en français, anglais et malagasy

Le français est la langue source et la langue par défaut. L'anglais et le malagasy sont servis sous `/en` et `/mg`.

## Adresses et langue

| Langue | Adresses | Exemple |
| --- | --- | --- |
| Français (défaut) | sans préfixe, inchangées | `/formations/licence-en-droit` |
| Anglais | `/en/…` | `/en/formations/licence-en-droit` |
| Malagasy | `/mg/…` | `/mg/formations/licence-en-droit` |

- Les **adresses (slugs) restent françaises** dans toutes les langues : une seule URL par contenu, on change seulement le préfixe.
- `routes/web.php` enregistre les routes publiques une fois par langue (`App\Support\Locales`, `App\Http\Middleware\SetLocale`).
  Les noms de route des langues préfixées commencent par `en.` / `mg.`.
- **Aucun lien du site n'a besoin de connaître la langue** : `url('/formations')` et `route('news.index')` donnent `/en/formations`
  sur une page anglaise, parce que `Locales::apply()` préfixe la racine des URL générées (`URL::forceRootUrl`). Les fichiers
  (images, CSS, JS) ne sont jamais préfixés (`URL::useAssetOrigin`).
- Le sélecteur **FR · EN · MG** (barre du haut et menu plein écran) renvoie vers la même page dans l'autre langue, requête conservée.
- SEO : `<html lang>`, `hreflang` (fr, en, mg, x-default), `og:locale`, plan du site avec versions alternatives par page.
- Le back-office, l'éditeur visuel et les mails internes restent en français.
- Les composants Livewire (contact, recherche) rejouent le middleware de langue de leur page (`Livewire::addPersistentMiddleware`).
- Date et heure : `translatedFormat()` suit la langue ; l'heure s'écrit « 14h30 » en français, « 14:30 » ailleurs (`Locales::time()`).

## Où vivent les traductions

| Quoi | Où | Comment |
| --- | --- | --- |
| Textes de l'interface (vues, composants, mails, messages) | `lang/en.json`, `lang/mg.json` | clé = la **phrase française** : `__('Voir la formation')` |
| Typographie française (espace insécable avant `: ? !`) | `lang/fr.json` | rétablie à l'affichage ; les clés restent à espaces simples |
| Textes éditoriaux longs (accueil, À propos, Soutenir) | `lang/{en,mg}/{home,about,support}.php` | même structure que `lang/fr/` |
| Validation des formulaires | `lang/mg/validation.php` (l'anglais : framework) | |
| Données des pages Admissions et Frais | `config/admissions.php`, `config/fees.php` (français) | traduites à l'affichage (`App\Support\Translated`) ; textes dans `lang/*.json` |
| Textes affichés par JavaScript | `App\Support\JsStrings::KEYS` → `window.uazI18n` | `t('phrase')` dans `resources/js/i18n.js` |
| Menus de navigation | libellés français en base | traduits par `lang/*.json` (`Locales::tr`) ; cache par langue |
| **Contenu éditorial** (pages, formations, actualités, événements, albums, équipe, témoignages, projets, facultés, réglages du site, textes d'images) | colonne JSON `translations` de chaque table | onglets **Traductions** du back-office |

### Contenu en base : `HasTranslations`

Les colonnes d'origine restent en français. `translations` = `{"en": {"title": "…"}, "mg": {…}}`. Sur une page `/en`, lire
`$formation->title` renvoie la traduction anglaise si elle est remplie, **sinon le français** : un contenu non traduit s'affiche
en français plutôt que vide. Les vues ne changent donc pas. Le HTML des champs riches est nettoyé à l'enregistrement. Les
listes (chiffres clés, horaires) ne traduisent que leurs libellés ; valeurs et suffixes viennent de l'original.

Un seeder idempotent traduit le contenu de structure (réglages, facultés, formations, titres de pages, projets, textes alternatifs
des photos connues) sans jamais écraser une traduction saisie : `php artisan db:seed --class=ContentTranslationsSeeder`.

## Ajouter ou modifier un texte

1. Écrire le texte **en français** dans la vue : `{{ __('Une phrase') }}` (`__(':n photos', ['n' => $n])` pour une variable).
2. Lancer `php artisan i18n:check --list` : la commande liste les phrases sans traduction en anglais et en malagasy.
3. Ajouter la phrase dans `lang/en.json` et `lang/mg.json` (mêmes variables `:nom`).
4. `tests/Feature/Public/TranslationsTest.php` échoue tant qu'une phrase manque ou qu'une variable a disparu.

## Mise en production

```
php artisan migrate --force                                   # colonnes « translations »
php artisan db:seed --class=ContentTranslationsSeeder --force # traductions du contenu de structure
npm run build
```

Les caches des menus se renouvellent seuls quand `lang/{langue}.json` change (la date du fichier fait partie de la clé).

## Limites connues

- Les contenus **importés** de l'ancien site (actualités, fonctions de l'équipe, descriptions d'images…) restent en français tant
  qu'ils ne sont pas traduits dans le back-office.
- La recherche trouve aussi le texte traduit, mais les lettres accentuées du malagasy peuvent y échapper (la colonne JSON est
  parcourue telle quelle).
- La page `/en/…` d'une adresse qui n'existe pas dans le routage (hors format des pages libres) affiche l'erreur 404 en français.
- Éditeur visuel : il édite le contenu français ; les traductions d'une page se saisissent dans son formulaire classique.
